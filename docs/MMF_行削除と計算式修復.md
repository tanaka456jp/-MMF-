# MMF取引台帳の安全な行削除・行追加

## 不具合の原因
以前の汎用F7/F8マクロは「行全体」を削除／コピーしていた。MMF台帳は K:Y に前行の残高・取得費を参照する計算式が並ぶため、通常の行削除で計算式が欠落・`#REF!`・参照先ずれを起こす場合がある。F8は取引の複製も起こしていた。

## 改修後の操作
1. VBAUpdaterで最新mainを反映し、Excelブックを保存して開き直す。
2. **一般口座／特定口座／MMF取引台帳**で削除する取引行を選択し、**F7**を押す。確認後、A:Jの入力データだけが上に詰められ、K:Yの移動平均・円換算・残高計算式は再構成される。連続・飛び飛びの複数行選択にも対応。
3. **F8**は選択行の直後に入力用の空行を挿入する。取引内容を複製しない。末尾の空行が不足すると、データを押し出さずに中止する。
4. 行操作後は計算を再実行し、口座別まとめ表の再集計も試みる。
5. 数式が既に壊れている場合は、当該口座シートで `Alt+F8` → **`MMF台帳_計算式修復`** を実行する。A:Jの元取引データは変更せず、K:Yのみを元台帳の正常なひな形から修復する。

Excelの標準「行全体の削除」で数式列が動いた場合は、イベント経由で自動修復を試み、ブック再起動時にも一般口座・特定口座の数式を検査する。ただしExcelのイベントが無効な環境などでは手動修復が必要。

## 安全対策
- タイトル・見出し（1～11行）の削除禁止
- 行操作の実行前に確認ダイアログ
- 正常な数式ひな形が得られない場合は入力変更前に停止
- 処理中のエラー時はA:J入力データのスナップショットを復元
- 元台帳の一般口座・特定口座の計算は独立して維持
- 他の「出納帳」等のF7/F8は従来どおり（MMF台帳だけ安全ルートに振分け）
- Excelマクロの操作は通常のCtrl+Zで戻せないため、VBAUpdater反映前にxlsmをバックアップする

**検証上の限界：** GitHub Actionsでは静的回帰テストを実施。Windows Excelの実機で行削除・挿入・保存・再オープン・印刷の一連動作は未確認。
